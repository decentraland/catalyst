# Content server configuration

The content server can be configured by environment variables.

## Env vars (WIP)

- `DENYLIST_URLS`: List of denylists used by the content server. Separated by new lines `\n`. Default: "https://config.decentraland.org/denylist"
- `DENYLIST_FILE_NAME`: Filename to be used as local denylist. Default: "denylist.txt"
- `SYNC_IGNORED_ENTITY_TYPES`: Ignored entity types, separated by comma. Prevents certain entities from being pulled from DAO catalysts. Default: ""
- `PENDING_DEPLOYMENT_TTL`: Fixed lifetime of a partial (multi-request) deployment, in milliseconds, counted from the arrival of its first request (before its body is read). Retries do not extend it, and a batch that is still being processed when it ends is rejected before its files are stored or the entity is published. Default: "3600000" (1h)
- `MAX_PENDING_DEPLOYMENTS_PER_DEPLOYER`: Max pending uploads per deployer, including expired uploads awaiting cleanup. Excess uploads get a `429` whose `Retry-After` is the next cleanup run (see `PENDING_DEPLOYMENTS_CLEANUP_INTERVAL`) once the oldest upload holding the quota has expired, since expired uploads stay charged until reclaimed; at least 1 s. Default: "10"
- `MAX_PENDING_BYTES_PER_DEPLOYER`: Max staged/reserved bytes per deployer. Only files an upload writes are charged: content already in storage when it arrives (before the upload, or from an earlier batch) is not stored again and not charged, though it still counts toward the scene size limit. Expired uploads stay charged until their content is deleted. Excess batches get a `429` with `Retry-After`, as for the upload count; an upload that alone needs more than this or `MAX_PENDING_BYTES` gets a `400`. Default: "1073741824" (1 GiB)
- `MAX_PENDING_BYTES`: Max staged/reserved bytes across the server, charged as for `MAX_PENDING_BYTES_PER_DEPLOYER`. Excess batches get a `429` with `Retry-After`, as for the upload count, over every deployer's uploads. Default: "53687091200" (50 GiB)
- `MAX_PARTIAL_UPLOAD_BYTES_PER_MINUTE`: Accepted partial batch bytes per deployer per fixed one-minute window, retries and files already in storage included. Excess batches get a `429` whose `Retry-After` is the time left in the window (at least 1 s); a single batch larger than this gets a `400`, still counted. Must be at least `MAX_UPLOAD_FILE_SIZE` plus 10 MiB (the entity file cap), since a file can't be split across batches. Default: "536870912" (512 MiB)
- `CONTENT_LOCK_CONNECTIONS`: Connections of the dedicated pool holding the advisory lock shared by deployments and excluded by garbage collection, in addition to `PG_POOL_SIZE`. Default: "16"
- `MAX_IN_FLIGHT_UPLOAD_BYTES`: Max POST /entities body bytes spooled to temporary files (under `UPLOAD_SPOOL_FOLDER`) at once across all clients, each file counting 16 KiB (its block, directory entry and inode) on top of its size; multipart framing is never spooled and isn't counted. Each request reserves at least `MIN_UPLOAD_RESERVATION_BYTES`. Excess uploads get a `503`. This also caps in-flight spool files at `MAX_IN_FLIGHT_UPLOAD_BYTES` / 16 KiB (262144 by default), ext4's default bytes-per-inode ratio. Partial batches are exempt from the per-IP daily quota (not the per-minute burst limit) and bounded by this, the per-source share below and their account's byte quotas instead. Must be at least `MAX_UPLOAD_TOTAL_SIZE` + 16 KiB × `MAX_UPLOAD_FILE_COUNT`. Default: `MAX_UPLOAD_TOTAL_SIZE` + 16 KiB × `MAX_UPLOAD_FILE_COUNT` or "4294967296" (4 GiB), whichever is larger
- `UPLOAD_SPOOL_FOLDER`: Node-local folder where POST /entities bodies are spooled while their request is handled; it needs room for `MAX_IN_FLIGHT_UPLOAD_BYTES` and for `MAX_IN_FLIGHT_UPLOAD_BYTES` / 16 KiB files (inodes). Its contents are managed by the server: each process owns a marked subfolder (restored if a temp-folder cleaner removes it, and no longer used once the process starts shutting down, when uploads get a `503`) and, on startup, removes the marked subfolders of exited processes on the same host (other entries are left untouched, but a dedicated folder is recommended), so it must never be shared between hosts (e.g. on the content storage volume). Its path must be at most 76 bytes long. Default: `<os temp dir>/catalyst-uploads`
- `MAX_IN_MEMORY_DEPLOYMENT_BYTES`: Max regular (non-partial) deployment file bytes read into memory at once; excess deployments get a `503`. Partial batches stream their content from disk; only their entity file counts, uploaded or read back from storage on a resume, for as long as the batch is staged. Must be at least `MAX_UPLOAD_TOTAL_SIZE`. Default: `MAX_UPLOAD_TOTAL_SIZE` or "2147483648" (2 GiB), whichever is larger
- `MIN_UPLOAD_RESERVATION_BYTES`: Least each POST /entities request reserves from `MAX_IN_FLIGHT_UPLOAD_BYTES` while it is received or handled, however small its declared body, covering its per-request overhead (form fields held in memory, parser buffers, open spool files, the socket); a larger request reserves its own size. It bounds concurrent uploads at `MAX_IN_FLIGHT_UPLOAD_BYTES` / `MIN_UPLOAD_RESERVATION_BYTES` (256 by default); excess uploads get a `503`. Must be at most `MAX_IN_FLIGHT_UPLOAD_BYTES`. Default: "16777216" (16 MiB)
- `TRUSTED_CLIENT_IP_HEADER`: Header holding the client address that the POST /entities rate limits and the per-source upload limits key on. Catalyst runs behind catalyst-owner's nginx, which forwards the connecting address in `X-Real-IP` (`proxy_set_header X-Real-IP $remote_addr` in `local/nginx/include/content_proxy.conf`); keyed on the socket address instead, every client would share nginx's address and so one budget. A request without the header is keyed on its socket address. Set it to the header another proxy writes, or to an empty string only when the process is reached directly (clients could otherwise pick their own address); empty logs a startup warning. Default: "x-real-ip"
- `MAX_CONCURRENT_UPLOADS_PER_SOURCE`: Max POST /entities bodies in flight at once from one client source (the `TRUSTED_CLIENT_IP_HEADER` address, else the socket address), checked before the body is read and held until the request ends; excess uploads get a `429` with `Retry-After`. Applies to regular deployments and partial batches alike. Default: "4"
- `MAX_IN_FLIGHT_UPLOAD_BYTES_PER_SOURCE`: Max declared POST /entities body bytes in flight at once from one client source; a body without a `Content-Length` counts as `MAX_UPLOAD_TOTAL_SIZE`. Excess uploads get a `429` with `Retry-After`. Must be at least `MAX_UPLOAD_TOTAL_SIZE`. Default: `MAX_UPLOAD_TOTAL_SIZE`
- `MAX_UPLOAD_FIELD_COUNT`: Max non-file form fields in a POST /entities request; more get a `413` naming the limit. The default fits `entityId`, `partial` and the three `authChain[i][type|payload|signature]` fields of the longest accepted auth chain (10 links). Default: "32"
- `MAX_UPLOAD_FIELD_SIZE`: Max bytes of one non-file form field value in a POST /entities request; a larger value gets a `413` naming the limit. Legitimate values are at most a few KiB (an EIP-1654 signature), so with the field count a request holds at most 1 MiB of fields in memory. Default: "32768" (32 KiB)
- `MULTIPART_UPLOAD_TIMEOUT_MS`: Max time to receive a POST /entities body; a slower upload is aborted with a `408` and its upload slot released. It stops once the body is received: flushing the spooled files afterwards has its own 60 s bound, past which the upload fails with a retryable `503`. Catalyst is expected behind a reverse proxy that buffers request bodies (catalyst-owner's nginx does by default), so a slow client occupies the proxy, not an upload slot. Default: "300000" (5 min)
- `PENDING_DEPLOYMENTS_CLEANUP_INTERVAL`: How often the job that reclaims expired pending deployments (their unreferenced staged content, then their accounting) runs, in milliseconds. Expired uploads stay charged against quotas until it reclaims them. Default: "300000" (5 min)
- `GARBAGE_COLLECTION_INTERVAL`: How often the incremental garbage collection sweep runs when `GARBAGE_COLLECTION` is enabled, in milliseconds. Default: "3600000" (1h)
